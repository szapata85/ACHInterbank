Hallazgo principal
- Existe colision entre rutas visuales Angular y rutas base proxyeadas al API para `/ach-cycles` y `/transactions`.
- La hipotesis de permisos insuficientes del usuario `admin` no queda respaldada por esta evidencia.

Evidencia de Nginx
- `nginx.conf` contiene `location = /ach-cycles` con `proxy_pass` al API.
- `nginx.conf` contiene `location = /transactions` con `proxy_pass` al API.
- No existe una regla equivalente `location /ach-cycles/` ni `location /transactions/` para esas pantallas visuales base.
- La regla final `location / { try_files $uri $uri/ /index.html; }` deja que Angular resuelva rutas no interceptadas.

Evidencia de Angular
- `app-routing.module.ts` define ruta visual `/ach-cycles`.
- `ach-cycles-routing.module.ts` define la vista lista en `path: ''` y la vista `/ach-cycles/nacha/export`.
- `app-routing.module.ts` define el modulo `transactions` en `/transactions`.
- `transactions-routing.module.ts` redirige `path: ''` a `list`, por lo que la ruta visual efectiva del listado es `/transactions/list`.

Comportamiento confirmado por HTTP
- `GET /ach-cycles` sin bearer: `401`.
- `GET /transactions` sin bearer: `401`.
- `GET /ach-cycles` con bearer interno: `200` y `Content-Type: application/json`.
- `GET /transactions` con bearer interno: `200` y `Content-Type: application/json`.
- Esto confirma que las rutas base directas llegan al API, no al `index.html` de Angular.

Comportamiento confirmado por navegacion interna SPA
- Desde dashboard, el menu visible contiene `Ciclos ACH`.
- Al hacer clic en `Ciclos ACH`, la SPA queda en `/ach-cycles` y la pantalla visual carga correctamente.
- La carga de esa vista dispara peticiones API internas como `GET /ach-cycles?page=1&pageSize=10`.
- Desde dashboard, el grupo `Transacciones` existe en el menu.
- Al hacer clic en `Transacciones`, la SPA navega a `/transactions/list` y la pantalla visual carga correctamente.
- La carga de esa vista dispara peticiones API internas como `GET /transactions?...`.
- Esto demuestra que la navegacion interna del router funciona, pero la navegacion directa del documento a las rutas base colisiona con el proxy.

Clasificacion de causa raiz probable
- `a) conflicto Nginx`: la ruta visual Angular esta interceptada por proxy API en las rutas base `/ach-cycles` y `/transactions`.
- `c) la pantalla existe solo bajo otra ruta`: aplica adicionalmente a `transactions`, cuya ruta visual efectiva desde UI es `/transactions/list`.
