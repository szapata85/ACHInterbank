# NAV4.2D — Inventario de acciones funcionales primarias/secundarias

## Método y universo inspeccionado

El inventario se construyó sobre el ZIP FULL NAV4.2C, sin Git, inspeccionando el copy visible de controles de acción y contrastándolo con el handler real y, cuando fue resoluble estáticamente, con la llamada de servicio/estado del componente. El scanner focal cubre definiciones de control, no instancias renderizadas en runtime:

- 482 `<button>` en templates HTML externos;
- 24 `<ui-boton>` en templates HTML externos;
- 61 `<button>` en templates inline/strings de producción TypeScript;
- 4 `<ui-boton>` en templates inline TypeScript;
- 7 botones creados programáticamente con `document.createElement('button')`;
- 4 labels configurados de acción `textoReintentar` en `ui-estado-error`.

**Total inspeccionado: 582 definiciones de control.** De ellas, **461** se caracterizaron como acciones funcionales dentro del universo NAV4.2D y **121** quedaron `OUT_OF_SCOPE` por ser navegación pura, paginación/retorno, cierre/toggle puramente presentacional u otro control no funcional para este incremento.

La columna `Gating directo` registra condiciones presentes en el propio control (`*ngIf`, `[disabled]`, `[deshabilitado]`, etc.). El gating heredado de contenedores se revisó focalmente para cada DRIFT y no se modificó; no se reescribieron permisos ni guardas.

## Convención de copy adoptada desde el efecto real

- **Guardar:** `Guardar` cuando el contexto inmediato es inequívoco; se agrega objeto cuando evita ambigüedad (`Guardar perfiles de acceso`, `Guardar configuración`, `Guardar horarios`).
- **Crear:** `Crear <objeto>` o una variante de dominio precisa; crear un Draft se mantiene como `Crear borrador`/`Crear versión en borrador` según la entidad.
- **Actualizar/recargar:** lecturas/reloads de estado vigente usan `Actualizar` y, si hace falta, el objeto (`Actualizar configuración`). `Recargar` no se usa como verbo visible de acción funcional en controles focales; sus ocurrencias remanentes están en acciones de snackbar/mensajes fuera de alcance.
- **Eliminar/desactivar/revocar/cancelar operación:** se preservan verbos distintos cuando el efecto persistente es distinto; no se suavizan acciones destructivas.
- **Upload:** el botón describe la operación (`Enviar archivo`, `Cargar certificado…`) y no reutiliza el nombre de la superficie de navegación. `Enviar archivo` de bulk ingestion permanece porque el handler registra/envía realmente el lote.
- **Download/export:** se conserva `Descargar` cuando el efecto entrega un archivo al usuario y `Exportar` cuando el dominio lo presenta como exportación; no se fusionan por estilo.
- **Retry:** se normaliza el control de reintento a `Reintentar`; mensajes explicativos cercanos quedan fuera de alcance.
- **Validate/preview/publish:** `Validar`, `Vista previa`/`Comparar…` y `Publicar` permanecen semánticamente separados. Se retiró `con backend` cuando sólo exponía implementación.
- **Clone:** se nombra el objeto cuando existe ambigüedad (`Clonar configuración`).
- **Generate:** se mantiene el objeto/resultante (`Generar archivo de auditoría`, `Generar archivo NACHA-M`, etc.).

## No logic delta

Los cambios de producción de NAV4.2D son exclusivamente strings visibles de controles. No se cambiaron handlers, eventos, service methods, endpoints, payloads, condiciones `[disabled]`, gating de permisos, invocaciones de confirmación, loading state ni navegación posterior. `NAV4_2D_COPY_DELTA.json` conserva las 49 líneas modificadas en 39 archivos SPA (38 de producción + 1 spec); el validador NAV4.2D revierte de forma determinística esas líneas y exige que el hash agregado de todo `web/ach-interbank-ui/src/app` vuelva exactamente al árbol NAV4.2C.

`NavigationNamingService` **no se reutilizó para nombrar acciones** y permanece byte-idéntico: su responsabilidad sigue siendo naming de rutas/superficies, no verbos de dominio. No se agregó ninguna taxonomía central de acciones, mapa route→label ni lookup adicional de navegación.

- **Mensajes/empty states:** toasts, snackbar, errores, confirm bodies y mensajes backend quedan fuera. Por eso pueden persistir frases como `volver a intentar` o `Recargar` dentro de mensajes/acciones de snackbar sin representar drift de botón focal.
- **Tooltips/ARIA no funcional:** no se hizo auditoría global; sólo se verificó coherencia accesible del mismo control cuando ya existía metadata asociada.

Como medida estructural de superficie pendiente se detectaron **394 `mat-label`**, **88 `<label>`**, **54 atributos `placeholder`** y **78 `mat-hint`**: **614 hooks de copy de formulario** potenciales. Estas cifras no equivalen a drift confirmado; sirven únicamente para acotar el siguiente inventario.

El siguiente incremento debe elegirse por el volumen restante. El inventario NAV4.2D recomienda, sujeto a decisión humana, **`NAV4.2E — labels/placeholders/hints de formularios`** como bloque visible de alto volumen y límites claros; no se ejecuta automáticamente.
