# NAV4.2E — Inventario de labels, placeholders y hints de formularios

Estado de referencia: NAV4.2D FULL. Este inventario cuenta hooks de copy de campos, no validaciones, botones, tablas ni mensajes. Los `mat-checkbox`, `mat-radio-button`, `mat-slide-toggle` y componentes `ui-campo-*` se incluyen como labels equivalentes cuando nombran el dato/control.

## Resumen exacto

- Hooks inspeccionados: **675**.
- Fields físicos únicos representados: **517**.
- Distribución por tipo: `MAT_LABEL` **370**, `HTML_LABEL` **143**, `PLACEHOLDER` **47**, `HINT` **75**, `ACCESSIBLE_FIELD_NAME` **40**.
- Clasificación final: `ALIGNED` **355**, `DRIFT` **36**, `TECHNICAL_TERM_LEGITIMATE` **24**, `DOMAIN_TERM_LEGITIMATE` **167**, `CONTEXTUAL_FIELD` **58**, `DYNAMIC_DATA` **35**, `OUT_OF_SCOPE` **0**.

`DRIFT` identifica hooks cuyo estado de entrada NAV4.2D tenía copy a corregir; todos aparecen ya con su copy final NAV4.2E y conservan el valor previo en la columna `Antes`.

## Convenciones durables observadas

- Labels: nombran el dato o dimensión funcional; se elimina exposición de nombres de propiedad como `PolicyVersion`, `ClearingHouseCycleConfig`, `EffectiveFrom`, `EffectiveTo`, `CorrelationId` y `FlowIds` cuando eran copy visible.
- Placeholders: se conservan cuando ejemplifican formato o valor técnico real. No se usa placeholder para sustituir el label.
- Hints: describen formato/comportamiento útil sin exponer innecesariamente que una decisión pertenece al “backend”; donde aplicaba se usa “el sistema”.
- Identificadores: se usa `ID de …`/`IDs de …` cuando el dato real es un identificador, sin modificar el binding ni el tipo.
- Términos técnicos legítimos: ACH, NACHA-M, MFT, SFTP, SOAP, WSDL, XSD, SHA-256/SHA256 cuando forma parte de un formato real, URL, IP, GUID, JSON, CSV y UTC se preservan.
- Datos dinámicos: opciones, catálogos, roles, fuentes contractuales y textos interpolados continúan dinámicos; no se reemplazan por strings hardcodeados.
- Select options: no se humanizan en este incremento y sus `value` permanecen intactos.

## Fuera de alcance detectado

- `mat-error`, mensajes de validación y mensajes backend permanecen para un incremento posterior. Por eso aún pueden existir `PolicyVersion`, `EffectiveTo`, `EffectiveFrom`, `flowIds`, `backend` u otros términos en mensajes no-field.
- Headers/columnas, opciones de selects/enums, toasts/snackbars, empty states, confirmaciones y tooltips generales no se modifican.
- El drift conocido UI `.xls` vs backend `.xlsx/.xlsm` permanece separado y no se corrige aquí.
